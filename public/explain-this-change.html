What it does

A pair of senior engineers, talking your change through

Any size of change

A pull request, a branch, your uncommitted work, one file, a range of lines or a single hunk. Add a question (“Is it safe to retry every request?”) and it is answered first.

Quick or Deep dive

Quick is about 30 seconds: the gist. Deep dive covers every part, then the proof and a closing review focus. Switch between them while it plays.

Pause and ask

Ask a question mid-walkthrough. The answer becomes a new chapter, lit up on the lines it is about.

Never a pass without proof

It shows the tests the change touches (or doesn't), the pull request's checks and, if you switch it on, your tests run before and after. Nothing says “tests pass” unless something shows it.

Never an invented reason

A “why” must come from a commit message, the pull request, an issue or the Claude Code session that wrote it, quoted and labelled. Otherwise it says “Intent not stated.”

Save to the pull request

Off until you switch it on. One comment headed with what to check, plus a searchable history. The comment never holds the code or Claude's reasoning.

For review apps

One script tag, then a button wherever you want one

Start the skill's helper on your computer, then drop the button into any review app. It works the same from Claude Code (“Explain this branch”), the command line, or JavaScript.

<!-- served by the helper on your own computer -->
<script src="http://127.0.0.1:4317/button.js"></script>

<!-- the hunk around line 34, with a question box -->
<explain-change file="src/retry.js" line="34" ask></explain-change>
Private code

Where your code goes

The guide in the download has the full table. The short version:

  • The change goes to your writer only: your own Claude Code sign-in (the default), or the Anthropic API with your own key. If you already use Claude Code on this code, nothing new leaves your computer.
  • Claude sees only what it is handed. It writes from an empty folder, with no tools, so it can't open other files or run anything.
  • Nothing else is sent anywhere. No analytics, no calls home. The page it makes loads nothing from the internet.
  • Off until you switch them on: posting to the pull request, running your tests (that runs the change's code), Google's voices (they hear the spoken words, never the code), and reading Claude Code's session notes.
Before you start

What you need

  • Claude Code, signed in. Or an Anthropic API key instead.
  • Node 20 or newer and git.
  • Optional: the GitHub command-line tool, signed in, for pull requests by number, their checks, and saving.
  • Optional: a Google AI Studio key for more natural voices, on your own account.
  • Cost: it comes out of your Claude plan like any other Claude Code request. On the practice project, Claude Code reported about $0.18 for one hunk with a question, and about $0.28 for a whole pull request plus a follow-up (the same work priced on the API). Asking the same thing again costs nothing.
Get started

Four steps to your first explanation

The download includes a full guide (README.md). This is the short version.

  1. Download the zip and unzip it. You'll get a folder called explain-this-change.
  2. Open Claude Code in your project and say: Copy the explain-this-change folder from my Downloads folder into this project's .claude/skills folder.
  3. Start Claude Code fresh so it notices the skill. To see it first without sending anything anywhere, say: Show me the explain-this-change practice page, offline.
  4. Ask for your first one. The first time, it installs its helpers, makes a settings file and checks everything is ready (a minute or two). Explain this branch.
Good to know

Plain English, and the honest limits

A plain-English mode, off by default

For people who don't read code: switch on product mode and the recap uses pictures of your running app instead of code, with no code words in the narration. If your app has a sign-in, give it a test account with tidy, made-up data: anything in it can appear in a picture.

It refuses rather than guesses

An explanation that fails the check is sent back to Claude once with the problems. If it fails again, it is refused, not shown. A built-in self-test proves each safeguard can say no.

Not tested yet. Version 1 was built and tested on one Mac, on the made-up practice project and a private practice pull request. Not yet tried:
  • Windows and Linux.
  • A review app served over https from the internet, calling the helper on your computer.
  • GitHub Enterprise.
  • Plain-English mode signing in to a real app (only the practice app so far).
  • The real format of Claude Code's session notes, beyond the practice files.

Tell me how it went

Your code is where it meets the real world, so I want to hear what it got wrong, what it missed, and what got in the way.

After your first few explanations, ask Claude “Help me fill in the explain-this-change feedback form.” It asks a few short questions and saves your answers as a file. Send that file to taz@madtaz.com.
